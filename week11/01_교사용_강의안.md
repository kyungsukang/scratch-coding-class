# 11주차 교사용 강의안 — 복습 + 디버깅 연습

## 학습 목표
- 지금까지 배운 개념(순차, 반복, 조건, 변수, 리스트, 신호, 나만의 블록)을 총복습한다.
- "디버깅"이 무엇인지 이해하고, 오류를 스스로 찾아 고치는 습관을 기른다.
- 블록을 하나씩 클릭해 실행해보며 문제를 좁혀나가는 방법을 익힌다.

## 준비물
- 학생 1인당 컴퓨터/노트북 1대, 스크래치 접속
- 이 강의안의 "버그 있는 코드 설명"을 학생들이 직접 스크래치로 만들어 재현한 뒤 고치는 방식으로 진행

## 시간 배분 (총 60분)

| 시간 | 활동 |
|---|---|
| 0~5분 | 도입: "디버깅"이 뭔지 소개 (벌레(bug)를 잡듯 오류를 찾는 것) |
| 5~15분 | 디버깅 방법 3가지 설명 |
| 15~50분 | 실습지의 버그 5개를 하나씩 찾아 고치기 |
| 50~55분 | 다같이 답 맞춰보기 |
| 55~60분 | 정리 + 다음 주(종합 실습) 예고 |

## 핵심 개념 설명 (5~15분)

**디버깅(Debugging)이란?**
- 프로그램의 오류(버그)를 찾아서 고치는 과정. 실력이 늘수록 자연스럽게 잘하게 되는 능력.

**디버깅 방법 3가지**
1. **블록 하나씩 클릭해서 실행해보기**: 스크래치는 블록을 클릭하면 그 블록(과 그 아래 연결된 블록들)만 바로 실행됨. 어디까지는 되고 어디부터 안 되는지 좁혀나갈 수 있음.
2. **변수 값을 무대에서 확인하기**: 체크박스를 켜서 변수가 지금 어떤 값인지 실시간으로 보기.
3. **예상 결과와 실제 결과 비교하기**: "이 블록을 실행하면 이렇게 될 거야"라고 먼저 예상한 뒤, 실제로 실행해서 다른 점을 찾기.

## 실습 진행 방법 (15~50분)

학생용 실습지에 있는 5개의 "버그 상황"을 순서대로 직접 스크래치에서 만들어보고(일부러 버그가 있는 상태로), 실행 결과를 관찰한 뒤 원인을 찾아 고치도록 안내합니다. 짝 활동으로 진행하면 서로 코드를 검토해주는 효과도 있습니다.

## 자주 발생하는 오류 & 대응 팁

| 상황 | 원인 | 해결 팁 |
|---|---|---|
| 버그를 못 찾고 포기하려 함 | 전체를 한 번에 보려고 함 | "일단 절반만 지우고 실행해보자"처럼 범위를 좁히는 법 안내 |
| 고쳤는데 다른 문제가 생김 | 원래 버그와 무관한 부분을 건드림 | 한 번에 하나씩만 고치고 실행해서 확인하는 습관 강조 |
| 정답을 바로 알려달라고 함 | 디버깅 경험 부족으로 답답함 | 힌트만 주고("이 블록의 순서를 다시 봐볼까?") 스스로 찾도록 유도 |
